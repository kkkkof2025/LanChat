# LanChat
一个极简的ai 对话程序，纯powershell .One script. Your model. Ready to chat. 


**一个纯 PowerShell 编写的极简大模型 API 测试工具与命令行对话客户端。**

无需编译，无需安装第三方依赖，无需登录外部账号。只要 Windows 电脑能够访问目标模型 API，即可测试模型接口、查看模型列表，并开始连续多轮对话。

项目面向局域网大模型、企业内网 AI 服务、离线环境和追求轻量化的开发者。它希望用尽可能少的依赖，解决一个简单而实际的问题：

**不必安装庞大的 AI 客户端，也能快速验证自己的模型服务是否可用，并立即与模型对话。**

## ✨ 核心特性

- **零第三方依赖**：基于 Windows 自带的 PowerShell 和 HTTP 请求能力，无需 Python、Node.js、额外模块或编译器。
- **无需公网依赖**：脚本本身不需要访问互联网，只向用户配置的模型 API 地址发送请求，适合受限网络和隔离环境。
- **模型列表检测**：调用 `GET /v1/models`，获取服务端公开的模型 ID。
- **聊天接口测试**：调用 `POST /v1/chat/completions`，发送测试提示词并查看模型回答。
- **连续多轮对话**：在同一交互会话中持续提问，快速体验内网模型。
- **请求耗时统计**：显示接口响应时间，辅助分析服务响应情况。
- **错误信息反馈**：尽可能展示 HTTP 状态码和服务端错误详情，帮助定位模型路由、权限或后端服务问题。
- **API Key 可选**：支持需要密钥和允许匿名访问的服务端。
- **轻量易审查**：单个 PowerShell 脚本即可运行，适合查看源码、审计和按需修改。

## 🎯 适用场景

- 企业内部部署的大模型 API 测试。
- 无法访问公网的办公电脑或隔离网络。
- 本地部署或局域网部署的 OpenAI 兼容模型。
- 调试 API 地址、模型 ID、接口兼容性和服务端错误。
- 在安装完整 AI 客户端之前，快速验证后端服务。
- 希望通过简单脚本直接与模型交互的开发者。

## 🚀 快速开始

### 1. 环境要求

- Windows 10 / Windows 11。
- Windows PowerShell 5.1 或更新版本的 PowerShell。
- 能够访问目标模型 API 的网络环境。
- 一个支持 OpenAI Chat Completions API 的服务端。

无需安装额外运行时，无需编译，也无需注册外部账号。

### 2. 获取脚本

下载或克隆仓库，取得：

`LanChat.ps1`

### 3. 运行脚本

在 PowerShell 中进入脚本所在目录，执行：

```powershell
.\LanChat.ps1
```

如果本机执行策略阻止了脚本运行，可以在确认源码可信后，仅对当前 PowerShell 进程临时放宽执行策略：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\LanChat.ps1
```


或者直接编写一个start.bat的脚本：
```powershell
@echo off
cd /d %~dp0
chcp 65001
powershell -NoProfile -ExecutionPolicy Bypass -Command "& { [Console]::OutputEncoding=[System.Text.Encoding]::UTF8; [Console]::InputEncoding=[System.Text.Encoding]::UTF8; & '.\LanChat.ps1' }"
pause
```



该设置仅作用于当前 PowerShell 进程，关闭该进程后即失效。

### 4. 配置模型 API

根据脚本提示输入以下信息：

| 配置项 | 说明 | 示例 |
|---|---|---|
| Base URL | 模型 API 基础地址 | `http://192.168.1.100:8000/v1` |
| API Key | 服务端要求的访问密钥 | `sk-xxxx` 或留空 |
| Model ID | 要调用的模型标识 | `my-model` |

请填写模型 API 地址，而不是模型管理后台的网页地址。

如果不确定 Model ID，可以先通过模型列表测试获取服务端返回的 ID，再填写准确的值。

### 5. 使用主菜单

| 菜单选项 | 功能 |
|---|---|
| `1` | 测试模型列表接口 `GET /models` |
| `2` | 测试聊天接口 `POST /chat/completions` |
| `3` | 进入交互聊天，连续进行多轮对话 |
| `4` | 连续执行模型列表和聊天测试 |
| `5` | 显示当前目标地址和模型信息，不显示 API Key |
| `0` | 退出程序 |

具体菜单以实际发布版本为准。

## 🔌 API 兼容性

当前版本主要使用以下 OpenAI 兼容接口：

| 接口 | 方法 | 用途 |
|---|---|---|
| `/v1/models` | `GET` | 获取可用模型列表 |
| `/v1/chat/completions` | `POST` | 发送聊天请求并获取回答 |

目标服务需要实现兼容的 Chat Completions 接口。

不同服务对 OpenAI API 的兼容程度可能存在差异。仅支持 `/v1/responses` 或其他专有协议的服务，不能保证直接兼容。

## 🛠️ 常见问题

### 1. 模型列表正常，但聊天返回 HTTP 503

这不一定是网络连接问题。

`GET /v1/models` 成功，只能说明模型列表接口能够正常响应；它并不能保证对应的推理后端已经就绪。

常见原因包括：

- 模型通道未配置或已被禁用。
- 上游推理服务不可用。
- 模型 ID 与服务端路由映射不一致。
- API Key 所属分组没有可用通道或调用权限。
- 服务端负载过高或后端暂时不可用。

建议结合错误正文和服务端日志进一步排查。

### 2. 返回 `model_not_found`

先确认模型 ID 是否与 `/v1/models` 返回的值完全一致。如果仍然失败，需要检查服务端的模型映射、路由配置和访问权限。

### 3. 无法连接目标地址

请检查：

- IP 地址与端口是否正确。
- API 服务是否已经启动。
- 当前电脑是否能够访问目标服务器。
- 防火墙是否阻止了连接。
- Base URL 是否包含正确的 API 路径。

### 4. 服务端不需要 API Key

如果目标服务允许匿名访问，API Key 可以留空。是否允许匿名调用由服务端决定。

## 🔐 隐私与安全

本项目适合内网和受限网络环境，但内网环境不意味着所有数据都天然安全。

- 脚本不需要访问公网，也不依赖外部账号系统。
- 当前版本不会主动将 API Key、提示词或回答写入本地文件。
- API Key 和对话内容仍会在运行期间经过本机内存，并发送到用户配置的目标服务端。
- 服务端是否记录、存储或转发请求，取决于服务端实现及其管理策略。
- 建议在使用前审查源码，并只连接可信的模型服务。
- 使用 HTTP 时，请注意网络中的其他设备可能观察到传输内容；如果环境支持，建议使用可信的 HTTPS 服务端。

**离线运行不等于自动保证数据安全。** 对于涉及商业机密、个人信息或其他敏感数据的场景，应同时遵循所在组织的数据安全要求。

## 🧭 项目定位与当前边界

这个项目希望保持小巧、直接、易于审查。

当前版本可以看作一个**极简模型客户端，也可以作为轻量级 Agent 的交互起点**。它支持连续多轮对话，但目前不具备完整 Agent 系统常见的自主规划、工具调用、函数调用或自动执行任务等能力。

当前版本暂不提供：

- 图形化桌面界面。
- 模型下载或部署管理。
- API 网关、模型通道和账号管理。
- 自动工具调用或命令执行。
- 完整的对话历史持久化管理。
- 对所有非标准 OpenAI API 实现的兼容保证。
